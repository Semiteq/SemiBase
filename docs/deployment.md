# Развёртывание

SemiBase разворачивается одной утилитой — `semibase.exe`. Это скрипт установки: одна команда
приводит экземпляр в заданное состояние и завершается. Утилита идемпотентна: каждый шаг сначала
проверяет состояние, затем создаёт недостающее. Повторный запуск безопасен. Пароли существующих
ролей меняются только при явной передаче соответствующего флага или переменной окружения.

Справка:

```powershell
.\semibase.exe --help              # список команд
.\semibase.exe site --help         # флаги конкретной команды
```

## Требования

| Компонент | Требование                                    |
| --------- | --------------------------------------------- |
| СУБД      | PostgreSQL 17; минимально поддерживаемая — 14 |
| Писатель  | Simple-Scada 2 с архивацией в PostgreSQL      |

Утилита — один исполняемый файл. Готовые сборки для Windows и Linux (x86-64) находятся на странице [Releases](https://github.com/Semiteq/SemiBase/releases/latest).

Каждый выпуск дополнительно публикует образ контейнера `ghcr.io/semiteq/semibase`. Он нужен
только тестовым стендам смежных проектов, которые встраивают эту утилиту в свои сборки. При
пусконаладке образ не используется — берите `semibase.exe` со страницы Releases.

Сборка из исходников: `go build -o semibase.exe ./cmd/semibase`.

## Команды

| Команда   | Действие                                                                                                                                                                 |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `site`    | Машина установки: настройки сервера через `ALTER SYSTEM`, затем архивная база, роли, права доступа, четыре таблицы SemiPlot и `public.trends`                            |
| `bench`   | Временный контейнер (тестовый стенд, база для разработки): то же самое без настроек сервера — константы памяти рассчитаны на машину установки и контейнеру ничего не дают |
| `version` | Печать ревизии сборки                                                                                                                                                     |

Обе команды заканчиваются проверкой: `semiplot` читает `public.trends` и версию схемы, вызывает
функцию регистрации новых перьев, пишет свои собственные таблицы и не может ни писать в архив, ни
менять версию схемы, ни создавать объекты в схеме `public`. Ненулевой код возврата означает, что заявленное состояние не достигнуто.

При обращении за поддержкой приложите вывод `semibase version` — он однозначно называет
сборку утилиты на машине.

## Пароли

Пароли утилита берёт из флагов, переменных окружения или файла `.env` в рабочем каталоге.
Приоритет: флаг, затем переменная окружения, затем `.env`. Образец файла — `.env.example`
в корне репозитория.

| Роль           | Флаг                | Переменная окружения       |
| -------------- | ------------------- | -------------------------- |
| `postgres`     | `--super-password`  | `SEMIBASE_SUPER_PASSWORD`  |
| `scada_writer` | `--writer-password` | `SEMIBASE_WRITER_PASSWORD` |
| `semiplot`     | `--plot-password`   | `SEMIBASE_PLOT_PASSWORD`   |

## Роли

Ролей четыре. Суперпользователя создаёт установщик СУБД, три остальные — утилита.

| Роль           | Кто использует             | Доступ                                              |
| -------------- | -------------------------- | --------------------------------------------------- |
| `postgres`     | Утилита развёртывания      | Суперпользователь: подключается сама утилита, ей же принадлежат таблицы `semiplot_*` |
| `scada_writer` | Simple-Scada 2             | Владеет архивными таблицами и пишет в них, создаёт дневные партиции, выполняет ретеншн |
| `semiplot`     | SemiPlot и другие клиенты  | Чтение `trends` и `messages`; чтение `semiplot_tags` и изменение настроек пера в ней, но не его `id`; чтение и запись `semiplot_groups` и `semiplot_pen_groups`; чтение `semiplot_meta`; вызов функции `semiplot_register_new_pens()` |
| `semiplot_registrar` | Никто не входит под ней | Владеет функцией `semiplot_register_new_pens()`: чтение `trends`, добавление строк в `semiplot_tags` |

Роль `semiplot` ведёт собственный каталог перьев: редактор SemiPlot сохраняет перо по тому же
соединению, по которому читает историю. Права выданы по таблицам, поэтому писать в архив она
не может — эту проверку утилита выполняет на каждом запуске.

Строка `semiplot_tags` привязана к номеру переменной SCADA. SemiPlot меняет в ней только
настройки пера: имя, единицы, формат, цвет, стиль линии, показ при старте и границы шкалы.
Добавить перо напрямую, удалить его или сменить ему `id` роль не может, и утилита на каждом запуске
проверяет, что эти три команды ей запрещены. Новые перья добавляет только функция
`semiplot_register_new_pens()`, и только для переменных, которые SCADA уже записала в `trends`.

Таблицы `semiplot_*` принадлежат суперпользователю: их создаёт то соединение, которое выполняет
DDL. Права `CREATE` в схеме `public` у роли `semiplot` нет — утилита забирает его у `PUBLIC`
на каждом запуске, потому что PostgreSQL 14 всё ещё выдаёт его всем по умолчанию, — поэтому
ничего сверх этих таблиц роль не добавит.

Таблицу `public.trends` утилита создаёт от имени `scada_writer`: владельцем должна быть та же
роль, от которой пишет SCADA, иначе `semiplot` получит доступ не тем путём, каким он работает
в эксплуатации. Утилита берёт роль командой `SET ROLE` на соединении суперпользователя и не
входит отдельно под `scada_writer`: владелец и права на таблицу выходят те же, а `pg_hba.conf`
править не придётся.

Пароли ролей нужны только на первом запуске — том, который эти роли создаёт. Когда роли уже
есть, достаточно пароля суперпользователя; пароль `semiplot` тогда лишь включает
дополнительную проверку входа под этой ролью (только по TCP).

## Таблицы SemiPlot

Утилита создаёт четыре таблицы и задаёт их схему. SemiPlot меняет настройки перьев в
`semiplot_tags` и ведёт группы в `semiplot_groups` и `semiplot_pen_groups`, `semiplot_meta` пишет
только сама утилита.

| Таблица               | Что хранит                                                                                  |
| --------------------- | ------------------------------------------------------------------------------------------- |
| `semiplot_tags`       | Перо: `id` из `trends`, имя, единицы, формат числа, цвет `#RRGGBB`, стиль линии, показ при старте, границы шкалы |
| `semiplot_groups`     | Имена групп перьев                                                                            |
| `semiplot_pen_groups` | Принадлежность пера группам. Перо может входить в несколько групп и ни в одну                 |
| `semiplot_meta`       | Одну строку: версию схемы                                                                     |

Перья появляются в `semiplot_tags` сами. SemiPlot при запуске и по кнопке обновления в редакторе
перьев вызывает функцию `semiplot_register_new_pens()`: она добавляет по строке на каждый номер
переменной из `trends`, у которого строки ещё нет, и возвращает число добавленных. Новое перо
называется своим номером, получает цвет из фиксированной палитры, по умолчанию скрыто при старте
и масштабируется автоматически. Перо переменной, которую SCADA перестала писать, остаётся: её
история по-прежнему лежит в `trends`. Номера переменных SCADA считаются неотрицательными: перо с
отрицательным номером остаётся без цвета, и цвет выбирает SemiPlot.

Функцией владеет отдельная роль `semiplot_registrar`, под которой нельзя войти. Функция
выполняется с её правами, а не с правами суперпользователя: чтение `trends` и добавление строк в
`semiplot_tags`, больше ничего. Вызвать функцию может только `semiplot`: право `EXECUTE`, которое
PostgreSQL выдаёт `PUBLIC` на любую новую функцию, утилита забирает. На архиве из 50 переменных за
один день первый вызов занимает около 13 мс, повторный — около 2 мс. Время растёт пропорционально
числу переменных, умноженному на число дневных партиций. Для 500 переменных за год это оценка, а
не замер: около 2,6 с на вызов, который ничего не добавляет, и около 4,8 с на вызов, который
добавляет все переменные.

Права ограничивают оператора SemiPlot, но не SCADA. Под ролью `scada_writer` работает сама
Simple-Scada 2 на той же машине, и ей доверяют: она владеет `trends` и и так может переписать или
удалить любую запись архива. Кто читает таблицу, тот выполняет код, который к ней добавил её
владелец: политика защиты строк на `trends` или представление на её месте вызывает свои функции с
правами читающей роли. Поэтому `scada_writer` может действовать от имени `semiplot`, когда та
читает `trends`, и от имени `semiplot_registrar`, когда выполняется функция. Права `semiplot`
держат другую границу: оператор SemiPlot меняет настройки перьев и группы, но не может добавить,
удалить или перенумеровать строку `semiplot_tags`. Отдельная роль-владелец всё равно нужна: если бы
функцией владел суперпользователь, `scada_writer` через представление получила бы права
суперпользователя на весь кластер. Под `semiplot_registrar` ей доступны только чтение `id` и
добавление строк в `semiplot_tags` и сама функция.

Версия схемы — нижняя граница, а не точное совпадение: SemiPlot отказывается работать
с базой, версия которой ниже нужной ей, и принимает базу с версией выше. Этот выпуск пишет `1`.

## Порядок ввода в эксплуатацию

Порядок важен: утилита выставляет права на чтение до того, как создаёт `public.trends`, поэтому
она отрабатывает до первого запуска SCADA.

1. Установить СУБД:

```powershell
winget install --id PostgreSQL.PostgreSQL.17 --exact
```

2. Задать пароли ролей: скопировать `.env.example` в `.env` рядом с утилитой и заполнить.

3. Выполнить одну команду:

```powershell
.\semibase.exe site
```

На выходе утилита гарантирует: настройки сервера применены, архивная база, три роли, права
и права по умолчанию созданы, четыре таблицы SemiPlot, функция `semiplot_register_new_pens()` и
`public.trends` (с партицией `tpdefault`) на месте, `semiplot` читает `public.trends`, вызывает
функцию регистрации перьев, пишет свои таблицы, не может добавить,
удалить или перенумеровать перо и не может писать в архив. Отдельной проверки после этого не требуется — она уже выполнена, её результат в коде
возврата.

4. Перезапустить службу PostgreSQL или перезагрузить машину. Все настройки, кроме
   `shared_buffers`, применяются сразу; `shared_buffers` — только после перезапуска.
   Утилита предупреждает об этом в последних строках вывода, пока перезапуск не сделан.

5. Запустить проект Simple-Scada против базы. Мы рассчитываем, что таблицу `trends` он застанет
   готовой, оставит её как есть и дальше создаст дневные партиции и `messages` сам. **Это
   предположение не проверено на реальном проекте.** На первом запуске включите
   `log_statement = 'all'` и прочитайте в журнале PostgreSQL, какие DDL-команды SCADA
   выдала: если она создаёт или изменяет `trends`, порядок ввода в эксплуатацию нужно
   пересмотреть.

6. Запустить SemiPlot. Перья появляются в `semiplot_tags` сами: по одному на каждую переменную,
   которую SCADA уже записала в `trends`, с настройками по умолчанию. Переменные, появившиеся
   позже, добавляет следующий запуск SemiPlot или кнопка обновления в редакторе перьев. Дальше их меняют в
   редакторе SemiPlot. Вручную перья не добавляют, а удалить перо может только суперпользователь.

7. Записать файл подключения SemiPlot `connection.yaml`: хост `127.0.0.1`, роль `semiplot` и её
   пароль. Часовой пояс в файле не указывают: SemiPlot работает на машине SCADA и читает архив в
   её часовом поясе.

Если проверка в конце сообщает, что `semiplot` не имеет доступа к `trends`, значит таблица была
создана раньше, чем выставлены права по умолчанию. Способ починки утилита называет в тексте
ошибки. Если проверка сообщает, что роль не может писать свою таблицу или, наоборот, держит
лишнее право на архив, в тексте ошибки названы таблица, операция и команда `GRANT` или `REVOKE`,
которая это чинит. Если роль может добавить, удалить или перенумеровать перо, в тексте ошибки
названа команда `REVOKE`, которая забирает лишнее право у `semiplot`, у `PUBLIC` или у роли, в
которую входит `semiplot`.

## Основные флаги

| Флаг               | По умолчанию    | Назначение                                                    |
| ------------------ | --------------- | ------------------------------------------------------------- |
| `--host`           | `localhost`     | Адрес сервера или каталог unix-сокета (`/var/run/postgresql`) |
| `--port`           | `5432`          | Порт сервера                                                  |
| `--database`       | `scada_archive` | Имя архивной базы                                             |
| `--expected-major` | не проверяется  | Требуемая мажорная версия сервера                             |

Полный перечень — `semibase <команда> --help`.
