# Развёртывание

SemiBase разворачивается установщиком `SemiBase-Setup.exe`. Один запуск приводит машину в рабочее
состояние: ставит PostgreSQL 17, если его нет, настраивает сервер, создаёт архивную базу, роли,
права и таблицы, перезапускает службу PostgreSQL, когда настройки этого ждут, и проверяет доступ
роли `semiplot`. Повторный запуск безопасен: каждый шаг сначала проверяет состояние, затем создаёт
недостающее.

Работу с базой установщик поручает утилите `semibase.exe`. Свои файлы установщик кладёт в одну
папку, `C:\Program Files\SemiBase`: утилита, значок, программа удаления `unins000.exe` и
журналы в `Logs`. Утилиту установщик кладёт туда первым делом при каждом запуске, в том числе
отказавшем. Вручную её запускают для [восстановления](#восстановление-после-отказа-установщика),
когда установщик отказывается работать, и на тестовых стендах.

## Требования

| Компонент | Требование                                                                                     |
| --------- | ---------------------------------------------------------------------------------------------- |
| СУБД      | PostgreSQL 17. Установщик работает только с 17; утилита на тестовых стендах принимает 14 и новее |
| Писатель  | Simple-Scada 2 с архивацией в PostgreSQL                                                       |

На странице [Releases](https://github.com/Semiteq/SemiBase/releases/latest) у каждого выпуска два
файла:

| Файл                            | Назначение                                                                                   |
| ------------------------------- | -------------------------------------------------------------------------------------------- |
| `SemiBase-Setup.exe`            | Установщик для Windows x86-64. Несёт утилиту и установщик PostgreSQL 17 от EDB, ничего не скачивает |
| `semibase_<версия>_linux_amd64` | Утилита для Linux, для тестовых стендов смежных проектов                                     |

Отдельного файла `semibase_<версия>_windows_amd64.exe` в выпусках больше нет: утилиту для
Windows несёт установщик.

Каждый выпуск также публикует образ контейнера `ghcr.io/semiteq/semibase` с той же Linux-сборкой.
Он нужен только тестовым стендам смежных проектов. При пусконаладке ни образ, ни Linux-сборка не
используются.

Сборка утилиты из исходников: `go build -o semibase.exe ./cmd/semibase`.

## Установщик

### Запуск без окон

Это основной способ. Установщик запускают в PowerShell от имени администратора: он ставит
PostgreSQL и управляет его службой.

```powershell
$setup = Start-Process -FilePath .\SemiBase-Setup.exe -ArgumentList '/VERYSILENT', '/SUPPRESSMSGBOXES', '/NORESTART', '/LANG=russian' -Wait -PassThru
$setup.ExitCode
```

Установщик — оконная программа, поэтому без `Start-Process -Wait` PowerShell не ждёт её
завершения и не получает код возврата.

| Ключ                | Назначение                                                        |
| ------------------- | ----------------------------------------------------------------- |
| `/VERYSILENT`       | Запуск без окон                                                   |
| `/SUPPRESSMSGBOXES` | Без диалоговых окон                                               |
| `/NORESTART`        | Без перезагрузки машины по завершении                             |
| `/LANG=russian`     | Язык сообщений установщика: `russian` или `english`               |

Без `/LANG` установщик берёт язык интерфейса Windows, а если это не русский и не английский,
русский. На этом языке он пишет причину отказа в журнал `setup-*.log`. Технические подробности
отказа (ключ реестра, код возврата, путь к журналу утилиты) он пишет строкой перед причиной и
всегда на английском. Вывод утилиты в журнале `site-*.log` тоже всегда на английском.

### Пароли по соглашению

У каждой роли пароль по умолчанию совпадает с её именем:

| Роль           | Пароль         | Переменная окружения, которая его заменяет |
| -------------- | -------------- | ------------------------------------------ |
| `postgres`     | `postgres`     | `SEMIBASE_SUPER_PASSWORD`                  |
| `scada_writer` | `scada_writer` | `SEMIBASE_WRITER_PASSWORD`, только для нового пользователя БД |
| `semiplot`     | `semiplot`     | нет                                        |

Эти пароли знает каждый, кто прочитал это руководство. Защищает базу другое: сервер принимает
подключения только с этой машины (`listen_addresses = 'localhost'`), и все клиенты работают на
ней же. Где нужен свой пароль, его меняют явно:

- `postgres`. Утилита и установщик пароль суперпользователя не меняют. Новый PostgreSQL 17
  установщик ставит с паролем из `SEMIBASE_SUPER_PASSWORD`, а без переменной с паролем
  `postgres`. Сменить его потом можно только вручную, например командой
  `& 'C:\Program Files\PostgreSQL\17\bin\psql.exe' -h localhost -U postgres -d postgres -c '\password postgres'`.
  После этого каждый запуск установщика и утилиты получает пароль в `SEMIBASE_SUPER_PASSWORD`,
  иначе утилита не подключится. То же относится к уже стоявшему PostgreSQL 17, у которого
  пароль суперпользователя не `postgres`.
- `scada_writer`. Пароль задаётся только при создании пользователя БД: из поля на странице
  паролей при новой установке PostgreSQL 17 или из `SEMIBASE_WRITER_PASSWORD`, а без них
  `scada_writer`. Пароль существующего пользователя БД не меняет ни установщик, ни утилита: тот же
  пароль хранит проект SCADA, и смена пароля остановила бы запись архива. Сменить его можно только
  вручную, например командой
  `& 'C:\Program Files\PostgreSQL\17\bin\psql.exe' -h localhost -U postgres -d postgres -c '\password scada_writer'`.
  Сразу после этого тот же пароль записывают в проект SCADA: Проект → Настройки → База данных.
  Новое подключение с прежним паролем сервер отклоняет.
- `semiplot`. Пароль не меняют. Каждый запуск установщика задаёт роли пароль `semiplot`, и на
  него рассчитан файл подключения SemiPlot. Переменную `SEMIBASE_PLOT_PASSWORD` перед запуском
  установщика не задают: утилита взяла бы пароль из неё.

Пароль передают переменной окружения. Строка `Read-Host` запрашивает его, и в историю команд
PowerShell попадает только сама строка, без пароля. Переменная живёт, пока окно открыто:

```powershell
$env:SEMIBASE_SUPER_PASSWORD = [Net.NetworkCredential]::new('', (Read-Host 'Пароль postgres' -AsSecureString)).Password
$env:SEMIBASE_WRITER_PASSWORD = [Net.NetworkCredential]::new('', (Read-Host 'Пароль scada_writer' -AsSecureString)).Password
```

`SEMIBASE_WRITER_PASSWORD` действует только на нового пользователя БД `scada_writer`, обычно при
первой установке. Если пользователь уже есть, утилита пишет в журнал `site` строку
`role scada_writer exists, credentials untouched; the given password applies to a new role only`
и пароль не меняет.

Пароли установщик берёт только из переменных окружения или со своей страницы паролей,
параметров командной строки для них нет. Свою командную строку установщик разбирает с потерями:
выбрасывает все `"`, а пароль с пробелом делит на два слова и лишнее слово молча пропускает.
Переменная доходит до установщика без изменений, с кавычками и пробелами.

Пароль `scada_writer` состоит только из печатных символов ASCII: латиница, цифры, пробел и знаки
препинания. SCADA входит с ним из настроек своего проекта, и как она кодирует другие символы, никто
не проверял.

Пароль суперпользователя ограничен, только когда установщик ставит PostgreSQL 17, то есть когда на
машине не зарегистрирован ни один PostgreSQL. Тогда он состоит из печатных символов ASCII, не
содержит `"`, не заканчивается на `\`, не начинается с `-` и не начинается и не заканчивается
пробелом. Пароль `postgres` эти правила проходит. Причина правил в установщике PostgreSQL: он
записывает пароль в кодировке ANSI, а утилита отправляет его в UTF-8; кавычка или конечная
обратная косая черта ломают его командную строку, а пароли с `-` или пробелом по краям на нём не
проверялись. С уже установленным PostgreSQL 17 пароль суперпользователя может быть любым:
установщик передаёт его утилите без изменений.

Переменная окружения не попадает ни в командную строку, ни в журналы установщика. При новой
установке PostgreSQL пароль суперпользователя на время создания кластера появляется в командной
строке процесса установщика EDB: так устроен этот установщик.

### Код возврата и журналы

| Код    | Значение                                                                                                         |
| ------ | ---------------------------------------------------------------------------------------------------------------- |
| `0`    | Машина в рабочем состоянии, все проверки пройдены                                                                |
| `7`    | Установщик отказался работать. Причина записана последней строкой в самом новом журнале `setup-*.log`, технические подробности строкой перед ней |
| другой | Сбой самой программы установки. Машина в рабочее состояние не приведена                                          |

Журналы лежат в `C:\Program Files\SemiBase\Logs`, паролей в них нет:

- `setup-<ггггммдд-ччммсс>.log` — причина отказа последней строкой. Строка перед ней, если она
  относится к этому отказу, называет технические подробности: ключ реестра, код возврата или путь
  к журналу утилиты.
- `site-<ггггммдд-ччммсс>.log` — полный вывод утилиты за каждый запуск, успешный или нет. Строки
  попадают в файл по мере вывода, поэтому журнал остаётся, даже если установщик прервали.

Создать или изменить что-либо в `C:\Program Files` может только администратор, поэтому обычный
пользователь не подменит ни журналы, ни утилиту.

### Запуск с окнами

Без `/VERYSILENT` установщик сначала спрашивает язык, и все его страницы и сообщения идут на
выбранном языке. Папку установки он не спрашивает: она всегда `C:\Program Files\SemiBase`.
Перед страницей готовности к установке идёт страница «Пароли пользователей БД». Если PostgreSQL
17 не зарегистрирован, на ней два поля, если зарегистрирован, одно, «Пароль администратора
PostgreSQL (пользователь БД postgres)». У каждого поля своё пояснение, а пароли видны при вводе:
это соглашения, а не секреты. Пояснение страницы при новой установке: «Установщик использует
пароли из полей. Для пустого поля установщик берёт пароль по умолчанию: имя пользователя БД
(postgres, scada_writer). PostgreSQL принимает подключения только с этого компьютера.», у
зарегистрированного PostgreSQL 17: «Установщик подключится к PostgreSQL 17 с паролем, указанным
ниже.».

Поле `postgres` заполнено из `SEMIBASE_SUPER_PASSWORD`, а без переменной паролем `postgres`. При
новой установке его пояснение «PostgreSQL 17 будет установлен с этим паролем; повторный запуск
установщика его не меняет.», у зарегистрированного PostgreSQL 17 «Если текущий пароль другой,
замените значение в поле.».

Поле «Пароль пользователя БД scada_writer» есть только при новой установке. Оно заполнено из
`SEMIBASE_WRITER_PASSWORD`, а без переменной паролем `scada_writer`. Его пояснение: «С этим
паролем SCADA записывает архив. Укажите этот пароль в проекте SCADA (Проект → Настройки → База
данных); повторный запуск установщика его не меняет.». У зарегистрированного PostgreSQL 17 поля
нет: пароль существующего пользователя БД установщик не меняет, а недостающего утилита создаёт с
паролем из `SEMIBASE_WRITER_PASSWORD`, без переменной с паролем `scada_writer`.

Ни одно поле не обязательно: пустое поле даёт пароль по соглашению. Если пароль нарушает
[правила](#пароли-по-соглашению), установщик показывает ошибку и остаётся на странице.

Страница готовности к установке показывает, что сделает установщик. Всё на ней он берёт из
реестра PostgreSQL, ничего не меняя и не подключаясь к серверу:

- Ни один PostgreSQL не зарегистрирован:

  ```text
  PostgreSQL 17 будет установлен
    Папка: C:\Program Files\PostgreSQL\17
    Папка данных: C:\Program Files\PostgreSQL\17\data
    Служба: postgresql-x64-17, тип запуска «Автоматически»
    Порт: 5432 (порт PostgreSQL по умолчанию); к нему подключаются SCADA и SemiPlot, только с этого компьютера
  ```

- PostgreSQL 17 зарегистрирован: «Найден установленный PostgreSQL 17, установщик настроит его»,
  строки «Папка: …», «Служба: …, тип запуска станет «Автоматически»» и «Порт: …; к нему
  подключаются SCADA и SemiPlot, только с этого компьютера» со значениями из реестра. Отдельным
  абзацем идёт предупреждение: «Установщик перезапускает службу PostgreSQL, если параметры
  сервера shared_buffers или listen_addresses отличаются от значений, которые задаёт установщик;
  при первой настройке сервера они отличаются. Подключения SCADA на время перезапуска прервутся:
  остановите SCADA перед установкой.»

Ниже идёт блок SemiBase: «Журналы: C:\Program Files\SemiBase\Logs» и база с пользователями БД.
При новой установке:

```text
Будут созданы база scada_archive и пользователи БД:
  scada_writer для записи архива SCADA, пароль <пароль из поля>
  semiplot для чтения архива в SemiPlot, пароль semiplot
```

У зарегистрированного PostgreSQL 17 заголовок «Будут созданы база scada_archive и пользователи
БД, если их нет:», строка `scada_writer` называет пароль из `SEMIBASE_WRITER_PASSWORD` или
`scada_writer` и добавляет «у существующего пароль не меняется», а строка `semiplot` кончается
словами «пароль сбрасывается на semiplot».

Если реестр уже показывает отказ, страница паролей пропускается, а страница готовности пишет
«Установка невозможна.», текст отказа, тот же, что попадёт в журнал, и «Нажмите «Отмена».». Так
бывает, когда зарегистрирован только PostgreSQL другой версии или регистрация PostgreSQL 17
неполная или повреждена. Этот отказ установщик пишет в журнал `setup-*.log` сразу, один раз за
запуск, так что журнал остаётся и после нажатия «Отмена».

Окончательные проверки установщик делает после нажатия «Установить». Отказ он показывает в своём
окне в поле, из которого текст можно выделить и скопировать, например путь к программе удаления,
и пишет в тот же журнал `setup-*.log`.

После успешной установки последняя страница называет всё, что нужно дальше. После новой установки
PostgreSQL 17 она называет пароль `scada_writer`, заданный этим запуском:

```text
PostgreSQL 17 настроен.

Укажите в проекте SCADA (Проект → Настройки → База данных):
сервер localhost
порт <порт>
база scada_archive
пользователь БД scada_writer
пароль <пароль scada_writer>

Подключение SemiPlot:
порт <порт>
пользователь БД semiplot
пароль semiplot

Журналы: C:\Program Files\SemiBase\Logs
```

После настройки уже зарегистрированного PostgreSQL 17 строка пароля `scada_writer` другая:
«пароль, заданный при создании пользователя (по умолчанию scada_writer)».

### Что делает установщик

Состояние PostgreSQL установщик определяет по реестру `HKLM\SOFTWARE\PostgreSQL`, который ведёт
установщик PostgreSQL от EDB, а не по списку служб. Строки проверяются сверху вниз, срабатывает
первая подходящая.

| На машине                                                                                                       | Установщик                                                                                                                                  |
| --------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| PostgreSQL 17 зарегистрирован (`Installations\postgresql-x64-17`), у него есть суперпользователь, каталог данных и имя службы с портом в реестре | Работает с ним, даже если зарегистрированы и другие версии. Порт и суперпользователя берёт из реестра. Службу переводит в автоматический запуск и запускает |
| PostgreSQL 17 зарегистрирован, но установка неполная: версия не 17.x, нет суперпользователя или нет `PG_VERSION` в каталоге данных | Отказывает. Так выглядит неудачная установка PostgreSQL                                                                        |
| PostgreSQL 17 зарегистрирован, но в ключе пусто имя службы (`Service ID`) или у службы в реестре нет порта (`Port`) | Отказывает: такую регистрацию установщик не чинит. Если службы с этим именем нет, отказывает `sc.exe config`; если порт в реестре неверный, отказывает утилита |
| Зарегистрирована другая версия, 17 нет                                                                          | Отказывает. Зарегистрированные ключи называет строка журнала перед отказом                                                                  |
| Ничего не зарегистрировано, но порт 5432 занят                                                                  | Отказывает: незнакомый сервер установщик не трогает                                                                                         |
| Ничего не зарегистрировано, но `C:\Program Files\PostgreSQL\17\data` не пуст                                    | Отказывает: существующие данные установщик не перезаписывает                                                                                |
| Ничего не зарегистрировано, порт свободен, каталога данных нет                                                  | Ставит PostgreSQL 17 с паролем суперпользователя из `SEMIBASE_SUPER_PASSWORD` или `postgres` и дальше работает с ним, как в первой строке   |

Новая установка PostgreSQL 17: порт 5432, служба `postgresql-x64-17`, суперпользователь `postgres`,
каталог данных `C:\Program Files\PostgreSQL\17\data`, локаль `C`, кодировка UTF8, без pgAdmin и
Stack Builder. Запустив службу, установщик сразу запускает утилиту, и та сама ждёт, пока служба
запустится и сервер начнёт принимать подключения:

```powershell
semibase.exe site --port <порт> --superuser <суперпользователь> --expected-major 17 --restart-service <служба>
```

С базой утилита поступает так:

| В базе                                       | Утилита                                                                                             |
| -------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| База `scada_archive` уже есть                | Использует её как есть                                                                              |
| Роли `scada_writer` нет                      | Создаёт её с переданным паролем, а без него с паролем `scada_writer`                                |
| Роль `scada_writer` есть                     | Оставляет прежний пароль, даже если пароль передан                                                  |
| Роль `semiplot` есть или её нет              | Создаёт роль или задаёт ей пароль `semiplot`                                                        |
| Таблица `public.trends` уже есть             | Не изменяет её. Если `semiplot` не может её читать, текст ошибки называет команду, которая это чинит |
| Кластер PostgreSQL 17 с локалью не `C`       | Использует как есть: новая база наследует локаль `template1` этого кластера                         |
| Сервер не версии 17                          | Отказывает                                                                                          |

Повторные запуски и сбои:

| Случай                                              | Результат                                                                                          |
| --------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| Повторный запуск установщика                        | Работает с установленным PostgreSQL 17 и перезапускает службу, только если настройки ждут перезапуска |
| Установщик PostgreSQL завершился с ошибкой          | Отказ; путь к журналу установщика PostgreSQL называет строка журнала перед отказом. Следующий запуск видит неполную установку и отказывает |
| Утилита отказала после установки PostgreSQL          | PostgreSQL остаётся. Повторный запуск с тем же паролем суперпользователя работает с ним              |
| Удаление SemiBase                                   | Удаляется утилита, журналы остаются                                                                |

Перезапуск службы разрывает подключения SCADA. Список настроек, которые ждут перезапуска, выводит
запрос `SELECT name FROM pg_settings WHERE pending_restart`. Если он не пуст, перед запуском
установщика на работающей установке остановите SCADA.

### Удаление

`unins000.exe` в `C:\Program Files\SemiBase` (или «Программы и компоненты») удаляет утилиту и
значок. PostgreSQL, его данные, роли и журналы в `C:\Program Files\SemiBase\Logs` остаются. Об
этом говорят оба окна программы удаления: вопрос «Удалить SemiBase? PostgreSQL 17 с архивом и
журналы останутся.» и итог «SemiBase удалён. Остались PostgreSQL 17 с архивом и журналы в папке
C:\Program Files\SemiBase\Logs.».

## Порядок ввода в эксплуатацию

Порядок важен: утилита выставляет права на чтение до того, как создаёт `public.trends`, поэтому
установщик отрабатывает до первого запуска SCADA.

1. Запустить установщик, как в разделе [запуск без окон](#запуск-без-окон), и убедиться, что код
   возврата `0`. При другом коде перейти к
   [восстановлению](#восстановление-после-отказа-установщика).

   Код `0` гарантирует: PostgreSQL 17 работает как служба с автоматическим запуском, настройки
   сервера применены, служба перезапущена, если они этого ждали. Архивная база, три роли, права и
   права по умолчанию созданы, пять таблиц SemiPlot, функция `semiplot_register_new_pens()` и
   `public.trends` (с партицией `tpdefault`) на месте. `semiplot` входит с паролем `semiplot`,
   читает `public.trends`, вызывает функцию регистрации перьев, пишет свои таблицы, не может
   добавить, удалить или перенумеровать перо и не может писать в архив. Отдельной проверки после
   этого не требуется.

2. Запустить проект Simple-Scada против базы. Проект подключают к `localhost` или `127.0.0.1`
   под ролью `scada_writer` с паролем, с которым она создана: `scada_writer`, если при первой
   установке не задали [другой](#пароли-по-соглашению) и не меняли его вручную. Сервер принимает
   подключения только с этой машины. Мы рассчитываем, что таблицу `trends` он
   застанет готовой, оставит её как есть и дальше создаст дневные партиции и `messages` сам.
   **Это предположение не проверено на реальном проекте.** На первом запуске включите
   `log_statement = 'all'` и прочитайте в журнале PostgreSQL, какие DDL-команды SCADA выдала:
   если она создаёт или изменяет `trends`, порядок ввода в эксплуатацию нужно пересмотреть.

3. Запустить SemiPlot и в редакторе перьев нажать «Обновить список перьев». Кнопка добавляет в
   `semiplot_tags` по перу на каждую переменную, которую SCADA уже записала в `trends`, с
   настройками по умолчанию. При запуске SemiPlot перья не добавляет: переменные, появившиеся
   позже, добавляет следующее нажатие кнопки. Дальше перья меняют в том же редакторе. Вручную их
   не добавляют, а удалить перо может только суперпользователь.

4. Записать файл подключения SemiPlot `connection.yaml`: хост `127.0.0.1`, порт PostgreSQL 17,
   роль `semiplot`, пароль `semiplot`. Порт при новой установке `5432`; у уже стоявшего
   PostgreSQL 17 он записан в значении `Port` ключа
   `HKLM\SOFTWARE\PostgreSQL\Services\postgresql-x64-17`, и журнал `site` называет его в последней
   строке, `Done: site completed against localhost:<порт>/scada_archive`. Часовой пояс в файле
   не указывают: SemiPlot работает на машине SCADA и читает архив в её часовом поясе.

Если проверка в конце работы утилиты не прошла, установщик возвращает `7`, а журнал `site`
называет причину. Если `semiplot` не имеет доступа к `trends`, значит таблица была создана раньше,
чем выставлены права по умолчанию; способ починки назван в тексте ошибки. Если роль не может писать
свою таблицу или, наоборот, держит лишнее право на архив, в тексте ошибки названы таблица, операция
и команда `GRANT` или `REVOKE`, которая это чинит. Если роль может добавить, удалить или
перенумеровать перо, в тексте ошибки названа команда `REVOKE`, которая забирает лишнее право у
`semiplot`, у `PUBLIC` или у роли, в которую входит `semiplot`.

## Восстановление после отказа установщика

Отказ установщика — это код возврата `7`. Восстановление идёт так:

1. Прочитать последнюю строку самого нового журнала
   `C:\Program Files\SemiBase\Logs\setup-*.log` и строку перед ней.
2. Найти в последней строке фрагмент из таблицы ниже и сделать то, что там сказано.
3. Запустить установщик снова.

Таблица приводит строки установщика, запущенного на русском. Установщик, запущенный на
английском (`/LANG=english` или английский интерфейс Windows), пишет те же сообщения
по-английски. Каждая строка сама называет следующий шаг. Технические подробности отказа в
строку на экране не входят: ключ реестра, код возврата или путь к журналу утилиты установщик
пишет на английском строкой перед ней, например `Registration
HKLM\SOFTWARE\PostgreSQL\Installations\postgresql-x64-17: no Super User.`. У отказов из-за
паролей, у отказа «Установщик остановлен из-за ошибки» и у отказов «Не удалось …» такой строки
нет, кроме «Не удалось задать службе»: у него строка перед отказом называет код возврата `sc.exe`.

Отказы из-за паролей и из-за состояния PostgreSQL установщик выдаёт до любых изменений в
PostgreSQL; до них он только кладёт утилиту в `C:\Program Files\SemiBase`. Отказ установщика
PostgreSQL или утилиты может прийти, когда PostgreSQL уже установлен или служба уже запущена.
Неверный пароль `postgres` уже стоящего PostgreSQL 17 обнаруживает только утилита, то есть
после того, как служба переведена в автоматический запуск и запущена.

| Фрагмент последней строки журнала | Что делать |
| --- | --- |
| `Пароль администратора PostgreSQL (пользователь БД postgres) недопустим`, `Пароль пользователя БД scada_writer содержит недопустимые символы` | Выбрать пароль по [правилам](#пароли-по-соглашению) или не задавать переменную, чтобы действовал пароль по соглашению. Правила для пароля `postgres` действуют только при новой установке PostgreSQL |
| `PostgreSQL 17 установлен не полностью` | Так выглядит неудачная установка PostgreSQL. Удалить её программой `uninstall-postgresql.exe`, путь к которой назван в строке, или через «Программы и компоненты», если строка называет их, и [дождаться конца удаления](#удаление-postgresql). Строка перед отказом называет ключ реестра и чего в нём не хватает |
| `PostgreSQL 17 установлен, но установщик не нашёл имя его службы или его порт` | В ключе PostgreSQL 17 пусто имя службы (`Service ID`), или у службы в реестре нет порта (`Port`); строка перед отказом называет оба ключа. Иначе удалить PostgreSQL программой, названной в строке, и [дождаться конца удаления](#удаление-postgresql) |
| `Установлен PostgreSQL другой версии` | Установщик работает только с PostgreSQL 17 и не ставит его рядом с другой версией. Строка перед отказом называет зарегистрированные ключи. Либо перенести данные другой версии на 17 через `pg_upgrade` в плановый простой, либо удалить другую версию, если её данные не нужны. Готовить другую версию утилитой вручную бесполезно: каждый следующий запуск установщика всё равно откажет |
| `Порт 5432 занят, а установленный PostgreSQL не найден` | На порту работает сервер, которого нет в реестре: служба, поставленная не установщиком EDB, сервер, запущенный вручную, или контейнер. Найти процесс: `Get-Process -Id (Get-NetTCPConnection -LocalPort 5432 -State Listen).OwningProcess`. Контейнер остановить: утилита закрыла бы его для подключений извне. Сервер PostgreSQL 17 на этой машине можно подготовить [утилитой вручную](#ручной-запуск-утилиты), иначе остановить его |
| `Папка C:\Program Files\PostgreSQL\17\data не пуста` | Данные остались после прерванной установки или после удаления PostgreSQL: удаление папку данных не трогает. Если данные не нужны, удалить папку. Установщик их никогда не перезаписывает |
| `Установщик PostgreSQL завершился с ошибкой` | Причина записана в журнале установщика PostgreSQL `%TEMP%\install-postgresql.log`; строка перед отказом называет этот путь и код возврата. Неполную установку удалить программой, названной в строке, и [дождаться конца удаления](#удаление-postgresql) |
| `Не удалось задать службе` | Чаще всего службы, названной в `Service ID` ключа PostgreSQL 17, не существует: регистрация осталась без своей службы. Строка называет ошибку Windows, строка перед ней код возврата `sc.exe`. Удалить PostgreSQL программой, названной в строке, и [дождаться конца удаления](#удаление-postgresql) |
| `Служба postgresql-x64-17 не запустилась` | Причина записана в журналах сервера, в папке, названной в строке, и в журнале событий Windows. Устранить её |
| `Неверный пароль администратора PostgreSQL` | Ввести текущий пароль в поле страницы паролей или передать его в `SEMIBASE_SUPER_PASSWORD`. Служба к этому моменту уже переведена в автоматический запуск и запущена. Строка перед отказом называет журнал `site` |
| `Утилита semibase.exe завершилась с ошибкой`, а журнал `site` называет `connecting to localhost:<порт>/` и отказ в подключении | В значении `Port` ключа `HKLM\SOFTWARE\PostgreSQL\Services\<служба>` записан не тот порт, на котором работает сервер. Исправить значение на `port` из `postgresql.conf` папки данных |
| `Утилита semibase.exe завершилась с ошибкой` | Причина записана в последних строках журнала `site`, путь к нему назван в строке. Если служба осталась остановленной, см. [ошибки перезапуска службы](#ошибки-перезапуска-службы) |
| `Не удалось ...`, `Установщик остановлен из-за ошибки` | Не скопировалась утилита в `C:\Program Files\SemiBase`, не запустился `powershell.exe`, установщик PostgreSQL или утилита, или не записался временный файл. Если не запустился установщик PostgreSQL или утилита, строка называет ошибку Windows; «Установщик остановлен из-за ошибки» называет текст ошибки установщика. Запустить установщик снова |

### Удаление PostgreSQL

`uninstall-postgresql.exe` завершается раньше, чем удаляет что-либо: работу делает его копия
`_uninstall*.000` в папке `%TEMP%`. Перед следующим запуском установщика дождитесь её завершения:

```powershell
while (Get-CimInstance Win32_Process | Where-Object { $_.Name -like '_uninstall*.000' }) { Start-Sleep -Seconds 1 }
```

Каталог данных удаление не трогает. Если он остался и не пуст, следующий запуск откажет из-за него.

### Ошибки перезапуска службы

Утилита запускает службу, только когда старый сервер завершил работу и порт перестал отвечать.
Если журнал `site` сообщает, что служба остановлена и такой останется, дождитесь, пока
`Test-NetConnection localhost -Port 5432` покажет `TcpTestSucceeded : False` и
`Get-Service postgresql-x64-17` покажет `Stopped`, и запустите службу командой
`Start-Service postgresql-x64-17`.

Если служба остановилась сразу после запуска, журнал `site` сообщает, отвечает ли сервер на порту.
Если ничего не отвечает, сервер завершился при старте. Причина записана в журнале сервера, в папке
`log` каталога данных. Если журнал называет настройку, которую записала утилита (например, серверу
не хватило памяти на `shared_buffers = 2GB`), удалите эту строку из `postgresql.auto.conf` в
каталоге данных и запустите службу командой `Start-Service postgresql-x64-17`. Повторный запуск
установщика запишет строку снова и так же остановит службу, поэтому сначала устраните причину.
Если сервер отвечает, служба не дождалась конца его старта, и сервер работает вне службы. Когда он
начнёт принимать подключения, остановите его командой `pg_ctl stop -D <каталог данных>`
(`pg_ctl.exe` лежит в папке `bin` установки PostgreSQL, каталог данных указан после `-D` в пути к
исполняемому файлу службы) и запустите службу командой `Start-Service postgresql-x64-17`.

Если установщик или утилиту прервали во время перезапуска (завершили процесс, вышли из системы),
служба может остаться остановленной. Проверьте её командой `Get-Service postgresql-x64-17` и, если
она остановлена, запустите командой `Start-Service postgresql-x64-17`.

### Ручной запуск утилиты

Для состояний, с которыми установщик не работает, утилиту запускают сами. Каждый запуск
установщика первым делом, ещё до проверки паролей, кладёт свою утилиту в
`C:\Program Files\SemiBase\semibase.exe`. Поэтому она есть и на машине, где установщик ни разу не
завершился успешно, и не нужно ни скачивать её, ни собирать. Заменить её может только
администратор, поэтому запускать её от имени администратора с паролями в окружении безопасно.

Утилита готовит только PostgreSQL 17 и откажет серверу другой версии. Ей нужны порт сервера,
суперпользователь и, если сервер работает как служба Windows, имя службы:

| Значение          | PostgreSQL 17 в реестре EDB                                                                                              | Сервер, которого нет в реестре                 |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------- |
| Порт              | Значение `Port` ключа `HKLM\SOFTWARE\PostgreSQL\Services\<служба>`; если его нет, `port` в `postgresql.conf` каталога данных | `5432`: на нём установщик и нашёл сервер       |
| Суперпользователь | Значение `Super User` ключа `HKLM\SOFTWARE\PostgreSQL\Installations\postgresql-x64-17`                                   | Тот, кто ставил сервер, обычно `postgres`      |
| Служба            | Значение `Service ID` того же ключа; если его нет или такой службы нет, поиск ниже                                        | Поиск ниже                                     |

Службу PostgreSQL находят по `pg_ctl` в пути к её исполняемому файлу. Каталог данных службы
указан там после `-D`:

```powershell
Get-CimInstance Win32_Service | Where-Object PathName -like '*pg_ctl*' | Format-List Name, State, StartMode, PathName
```

Утилита не работает с отключённой или остановленной службой, поэтому службу переводят в
автоматический запуск и запускают. Дальше в окне PowerShell от имени администратора, подставив
значения из таблицы:

```powershell
$port = 5432
$superuser = 'postgres'
$service = 'postgresql-x64-17'
Set-Service $service -StartupType Automatic; Start-Service $service
# только если пароль суперпользователя не postgres
$env:SEMIBASE_SUPER_PASSWORD = [Net.NetworkCredential]::new('', (Read-Host 'Пароль postgres' -AsSecureString)).Password
& 'C:\Program Files\SemiBase\semibase.exe' site --port $port --superuser $superuser --expected-major 17 --restart-service $service
$LASTEXITCODE
```

Пароли `scada_writer` и `semiplot` утилита берёт по [соглашению](#пароли-по-соглашению), как и
установщик: создаёт недостающий `scada_writer` с паролем `scada_writer`, существующему пароль не
меняет, а `semiplot` задаёт пароль `semiplot`. Перед любыми изменениями утилита сверяет каталог
после `-D` в пути к исполняемому файлу службы с каталогом данных сервера на порту. Если они не
совпадают, `--restart-service` называет не ту службу, и утилита завершается с ошибкой, ничего не
изменив.

Если сервер работает не как служба Windows, например запущен вручную через `pg_ctl start`, строку
`Set-Service` и флаг `--restart-service $service` убирают. Тогда утилита сообщает, какие настройки
ждут перезапуска, и сервер перезапускают вручную. Контейнер так не готовят: после перезапуска
сервер слушает только локальный интерфейс, и контейнер закрывается для подключений извне.

Код `0` значит то же, что код `0` установщика.

## Утилита semibase.exe

Утилита — скрипт установки: одна команда приводит экземпляр в заданное состояние и завершается.
Пароль суперпользователя она не меняет никогда, пароль `semiplot` задаёт на каждом запуске, а
пароль `scada_writer` задаёт только при создании роли: существующей роли он не меняется, даже
если передан флагом или переменной окружения.

```powershell
.\semibase.exe --help              # список команд
.\semibase.exe site --help         # флаги конкретной команды
```

| Команда   | Действие                                                                                                                                                                 |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `site`    | Машина установки: настройки сервера через `ALTER SYSTEM`, затем архивная база, роли, права доступа, пять таблиц SemiPlot и `public.trends`                               |
| `bench`   | Временный контейнер (тестовый стенд, база для разработки): то же самое без настроек сервера: память в них рассчитана на машину установки, а прослушивание только локального интерфейса закрыло бы контейнер от клиентов |
| `version` | Печать ревизии сборки                                                                                                                                                     |

Обе команды заканчиваются проверкой: `semiplot` читает `public.trends` и версию схемы, вызывает
функцию регистрации новых перьев, пишет свои собственные таблицы и не может ни писать в архив, ни
менять версию схемы, ни создавать объекты в схеме `public`. Ненулевой код возврата означает, что
заявленное состояние не достигнуто.

При обращении за поддержкой приложите вывод `semibase version`: он однозначно называет сборку
утилиты на машине.

### Пароли

Пароль утилита берёт из флага, затем из переменной окружения, затем по соглашению: пароль роли
совпадает с её именем. Файлов с паролями утилита не читает и сама их не записывает. Флаг с
паролем, набранный в командной строке, PowerShell сохраняет в истории команд на диске. Поэтому
пароли задают переменными окружения, а значение вводят по запросу `Read-Host`, как в
[ручном запуске утилиты](#ручной-запуск-утилиты).

Команды, которые задают пароль роли, в журнал PostgreSQL не попадают: ни при
`log_statement = 'all'`, ни при журналировании медленных или ошибочных запросов. На соединениях
суперпользователя утилита отключает журналирование своих команд, поэтому роль, под которой она
подключается, должна быть суперпользователем.

| Роль           | Флаг                | Переменная окружения       | По соглашению  | Утилита задаёт пароль |
| -------------- | ------------------- | -------------------------- | -------------- | --------------------- |
| `postgres`     | `--super-password`  | `SEMIBASE_SUPER_PASSWORD`  | `postgres`     | Никогда               |
| `scada_writer` | `--writer-password` | `SEMIBASE_WRITER_PASSWORD` | `scada_writer` | Только при создании роли |
| `semiplot`     | `--plot-password`   | `SEMIBASE_PLOT_PASSWORD`   | `semiplot`     | На каждом запуске     |

Пароль `scada_writer`, переданный или по соглашению, получает только роль, которую создаёт этот
запуск; существующая роль сохраняет свой, и утилита пишет `exists, credentials untouched; the given
password applies to a new role only`, если пароль передан. Сменить его можно только
[вручную](#пароли-по-соглашению). Роль `semiplot` получает свой пароль на каждом запуске, и утилита
проверяет вход под ней по TCP. При подключении через каталог unix-сокета эта проверка пропускается.

### Основные флаги

| Флаг                | По умолчанию    | Назначение                                                    |
| ------------------- | --------------- | ------------------------------------------------------------- |
| `--host`            | `localhost`     | Адрес сервера или каталог unix-сокета (`/var/run/postgresql`) |
| `--port`            | `5432`          | Порт сервера                                                  |
| `--database`        | `scada_archive` | Имя архивной базы                                             |
| `--superuser`       | `postgres`      | Суперпользователь, под которым подключается утилита           |
| `--expected-major`  | не проверяется  | Требуемая мажорная версия сервера                             |
| `--restart-service` | не задан        | Только `site` в Windows: служба PostgreSQL, которую утилита перезапускает, если настройки ждут перезапуска. Требует `--host` `localhost`, `127.0.0.1` или `::1` и запуска от имени администратора. Отключённую, остановленную или обслуживающую другой каталог данных службу утилита не трогает и завершается с ошибкой; только что запущенную службу ждёт до двух минут |

Полный перечень — `semibase <команда> --help`.

## Роли

Ролей четыре. Суперпользователя создаёт установщик СУБД, три остальные — утилита.

| Роль           | Кто использует             | Доступ                                              |
| -------------- | -------------------------- | --------------------------------------------------- |
| `postgres`     | Утилита развёртывания      | Суперпользователь: подключается сама утилита, ей же принадлежат таблицы `semiplot_*` |
| `scada_writer` | Simple-Scada 2             | Владеет архивными таблицами и пишет в них, создаёт дневные партиции, выполняет ретеншн |
| `semiplot`     | SemiPlot и другие клиенты  | Чтение `trends` и `messages`; чтение `semiplot_tags` и изменение настроек пера в ней, но не его `id`; чтение и запись `semiplot_groups`, `semiplot_pen_groups` и `semiplot_markers`; чтение `semiplot_meta`; вызов функции `semiplot_register_new_pens()` |
| `semiplot_registrar` | Никто не входит под ней | Владеет функцией `semiplot_register_new_pens()`: чтение `trends`, добавление строк в `semiplot_tags` |

Роль `semiplot` ведёт собственный каталог перьев и метки времени: редактор SemiPlot сохраняет перо по тому же
соединению, по которому читает историю. Права выданы по таблицам, поэтому писать в архив она
не может — эту проверку утилита выполняет на каждом запуске.

Строка `semiplot_tags` привязана к номеру переменной SCADA. SemiPlot меняет в ней только
настройки пера: имя, единицы, формат, цвет, стиль линии, показ при старте, границы шкалы при старте
и логарифмическая шкала при старте. Добавить перо напрямую, удалить его или сменить ему `id` роль
не может, и утилита на каждом запуске проверяет, что эти три команды ей запрещены. Новые перья
добавляет только функция `semiplot_register_new_pens()`, и только для переменных, которые SCADA уже
записала в `trends`.

Таблицы `semiplot_*` принадлежат суперпользователю: их создаёт то соединение, которое выполняет
DDL. Права `CREATE` в схеме `public` у роли `semiplot` нет — утилита забирает его у `PUBLIC`
на каждом запуске, потому что PostgreSQL 14 всё ещё выдаёт его всем по умолчанию, — поэтому
ничего сверх этих таблиц роль не добавит.

Таблицу `public.trends` утилита создаёт от имени `scada_writer`: владельцем должна быть та же
роль, от которой пишет SCADA, иначе `semiplot` получит доступ не тем путём, каким он работает
в эксплуатации. Утилита берёт роль командой `SET ROLE` на соединении суперпользователя и не
входит отдельно под `scada_writer`: владелец и права на таблицу выходят те же, а `pg_hba.conf`
править не придётся.

## Таблицы SemiPlot

Утилита создаёт пять таблиц и задаёт их схему. SemiPlot меняет настройки перьев в
`semiplot_tags`, ведёт группы в `semiplot_groups` и `semiplot_pen_groups` и метки времени в
`semiplot_markers`, а `semiplot_meta` пишет только сама утилита.

| Таблица               | Что хранит                                                                                  |
| --------------------- | ------------------------------------------------------------------------------------------- |
| `semiplot_tags`       | Перо: `id` из `trends`, имя, единицы, формат числа, цвет `#RRGGBB`, стиль линии, показ при старте, границы шкалы при старте, логарифмическая шкала при старте |
| `semiplot_groups`     | Имена групп перьев                                                                            |
| `semiplot_pen_groups` | Принадлежность пера группам. Перо может входить в несколько групп и ни в одну                 |
| `semiplot_markers`    | Метки времени на графике: момент и необязательная подпись длиной до 80 символов. Метка не привязана к дневной партиции архива и переживает её удаление |
| `semiplot_meta`       | Одну строку: версию схемы                                                                     |

Перья появляются в `semiplot_tags` по кнопке «Обновить список перьев» в редакторе перьев SemiPlot,
при запуске SemiPlot их не добавляет. Кнопка вызывает функцию `semiplot_register_new_pens()`: она
добавляет по строке на каждый номер переменной из `trends`, у которого строки ещё нет, и возвращает
число добавленных. Новое перо называется своим номером, получает цвет из фиксированной палитры, по
умолчанию скрыто при старте, масштабируется автоматически и открывается на линейной шкале. Перо
переменной, которую SCADA перестала писать, остаётся: её история по-прежнему лежит в `trends`.
Номера переменных SCADA считаются неотрицательными: перо с отрицательным номером остаётся без
цвета, и цвет выбирает SemiPlot.

Функцией владеет отдельная роль `semiplot_registrar`, под которой нельзя войти. Функция
выполняется с её правами, а не с правами суперпользователя: чтение `trends` и добавление строк в
`semiplot_tags`, больше ничего. Вызвать функцию может только `semiplot`: право `EXECUTE`, которое
PostgreSQL выдаёт `PUBLIC` на любую новую функцию, утилита забирает. На архиве из 50 переменных за
один день первый вызов занимает около 13 мс, повторный — около 2 мс. Время растёт пропорционально
числу переменных, умноженному на число дневных партиций. Для 500 переменных за год это оценка, а
не замер: около 2,6 с на вызов, который ничего не добавляет, и около 4,8 с на вызов, который
добавляет все переменные.

Права ограничивают оператора SemiPlot, но не SCADA. Под ролью `scada_writer` работает сама
Simple-Scada 2 на той же машине, и ей доверяют: она владеет `trends` и и так может переписать или
удалить любую запись архива. Кто читает таблицу, тот выполняет код, который к ней добавил её
владелец: политика защиты строк на `trends` или представление на её месте вызывает свои функции с
правами читающей роли. Поэтому `scada_writer` может действовать от имени `semiplot`, когда та
читает `trends`, и от имени `semiplot_registrar`, когда выполняется функция. Права `semiplot`
держат другую границу: оператор SemiPlot меняет настройки перьев, группы и метки времени, но не может добавить,
удалить или перенумеровать строку `semiplot_tags`. Отдельная роль-владелец всё равно нужна: если бы
функцией владел суперпользователь, `scada_writer` через представление получила бы права
суперпользователя на весь кластер. Под `semiplot_registrar` ей доступны только чтение `id` и
добавление строк в `semiplot_tags` и сама функция.

Версия схемы — нижняя граница, а не точное совпадение: SemiPlot отказывается работать
с базой, версия которой ниже нужной ей, и принимает базу с версией выше. Этот выпуск пишет `1`.
