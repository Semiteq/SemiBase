# Развёртывание

SemiBase разворачивается установщиком `SemiBase-Setup.exe`. Один запуск приводит машину в рабочее
состояние: ставит PostgreSQL 17, если его нет, настраивает сервер, создаёт архивную базу, роли,
права и таблицы, перезапускает службу PostgreSQL, когда настройки этого ждут, и проверяет доступ
роли `semiplot`. Повторный запуск безопасен: каждый шаг сначала проверяет состояние, затем создаёт
недостающее.

Работу с базой установщик поручает утилите `semibase.exe` и кладёт её копию в
`C:\Program Files\SemiBase` (или в папку, выбранную при установке). Каждый запуск установщика,
в том числе отказавший, кладёт ещё одну копию в `C:\Program Files\SemiBase Setup`. Вручную
утилиту запускают для [восстановления](#восстановление-после-отказа-установщика), когда
установщик отказывается работать, и на тестовых стендах.

## Требования

| Компонент | Требование                                                                                     |
| --------- | ---------------------------------------------------------------------------------------------- |
| СУБД      | PostgreSQL 17. Установщик работает только с 17; утилита на тестовых стендах принимает 14 и новее |
| Писатель  | Simple-Scada 2 с архивацией в PostgreSQL                                                       |

На странице [Releases](https://github.com/Semiteq/SemiBase/releases/latest) у каждого выпуска два
файла:

| Файл                            | Назначение                                                                                   |
| ------------------------------- | -------------------------------------------------------------------------------------------- |
| `SemiBase-Setup.exe`            | Установщик для Windows x86-64. Несёт утилиту и установщик PostgreSQL 17 от EDB, ничего не скачивает |
| `semibase_<версия>_linux_amd64` | Утилита для Linux, для тестовых стендов смежных проектов                                     |

Отдельного файла `semibase_<версия>_windows_amd64.exe` в выпусках больше нет: утилиту для
Windows несёт установщик.

Каждый выпуск также публикует образ контейнера `ghcr.io/semiteq/semibase` с той же Linux-сборкой.
Он нужен только тестовым стендам смежных проектов. При пусконаладке ни образ, ни Linux-сборка не
используются.

Сборка утилиты из исходников: `go build -o semibase.exe ./cmd/semibase`.

## Установщик

### Запуск без окон

Это основной способ. Установщик запускают в PowerShell от имени администратора: он ставит
PostgreSQL и управляет его службой. Пароли передают переменными окружения:

```powershell
$env:SEMIBASE_SUPER_PASSWORD = [Net.NetworkCredential]::new('', (Read-Host 'Пароль postgres' -AsSecureString)).Password
$env:SEMIBASE_WRITER_PASSWORD = [Net.NetworkCredential]::new('', (Read-Host 'Пароль scada_writer' -AsSecureString)).Password
$setup = Start-Process -FilePath .\SemiBase-Setup.exe -ArgumentList '/VERYSILENT', '/SUPPRESSMSGBOXES', '/NORESTART' -Wait -PassThru
$setup.ExitCode
```

Каждая строка `Read-Host` запрашивает пароль, и в историю команд PowerShell попадает только сама
строка, без пароля. Переменные живут, пока окно открыто. Установщик — оконная программа, поэтому
без `Start-Process -Wait` PowerShell не ждёт её завершения и не получает код возврата.

### Параметры и пароли

| Параметр                   | Переменная окружения       | Назначение                                                                                                   |
| -------------------------- | -------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `/SUPERPASSWORD=<пароль>`  | `SEMIBASE_SUPER_PASSWORD`  | Пароль суперпользователя PostgreSQL. Нужен при каждом запуске, установщик его нигде не хранит. При новой установке PostgreSQL он становится паролем `postgres` |
| `/WRITERPASSWORD=<пароль>` | `SEMIBASE_WRITER_PASSWORD` | Пароль `scada_writer`. Нужен, когда роли ещё нет, то есть при первой установке. Если роль есть, пустое значение оставляет ей прежний пароль, а непустое заменяет его, и SCADA дальше входит только с новым. При повторных запусках значение оставляют пустым |
| `/VERYSILENT`              |                            | Запуск без окон                                                                                              |
| `/SUPPRESSMSGBOXES`        |                            | Без диалоговых окон                                                                                          |
| `/NORESTART`               |                            | Без перезагрузки машины по завершении                                                                        |

Переменная окружения используется, только когда параметра нет.

Роли `semiplot` установщик на каждом запуске задаёт пароль `semiplot`. На этот пароль рассчитан
файл подключения SemiPlot, поэтому параметра для него нет.

Пароль `scada_writer` состоит только из печатных символов ASCII: латиница, цифры, пробел и знаки
препинания. SCADA входит с ним из настроек своего проекта, и как она кодирует другие символы, никто
не проверял.

Пароль суперпользователя ограничен, только когда установщик ставит PostgreSQL 17, то есть когда на
машине не зарегистрирован ни один PostgreSQL. Тогда он состоит из печатных символов ASCII, не
содержит `"`, не заканчивается на `\`, не начинается с `-` и не начинается и не заканчивается
пробелом. Причина в установщике PostgreSQL: он записывает пароль в кодировке ANSI, а утилита
отправляет его в UTF-8; кавычка или конечная обратная косая черта ломают его командную строку, а
пароли с `-` или пробелом по краям на нём не проверялись. С уже установленным PostgreSQL 17
пароль суперпользователя может быть любым: установщик передаёт его утилите без изменений.

Все `"` из своей командной строки установщик выбрасывает, поэтому пароль с кавычкой передают
только переменной. Пароль с пробелом тоже проще передать переменной. Параметром он доходит,
только если кавычки стоят вокруг всего параметра в самой командной строке. В `Start-Process`
внешние кавычки снимает PowerShell, поэтому их пишут внутри строки:
`-ArgumentList '"/SUPERPASSWORD=two words"'`. Установщик отвергает параметр, значение которого
дошло не таким, каким его набрали. Отвергает он и любое слово командной строки, кроме параметров
паролей и ключей самого Inno Setup, таких как `/VERYSILENT`, `/LOG` и `/DIR=`, ведь пароль с
пробелом без кавычек распадается на два слова. Если же после пробела стоит ключ Inno Setup, как в
пароле `x /NOCANCEL`, установщик примет только `x`, поэтому пароль с пробелом без кавычек не
передают.

Пароль, переданный параметром, виден в списке процессов, пока установщик работает, и попадает в
историю команд PowerShell, если его набрали в строке. С параметром `/LOG` установщик пишет в свой
журнал всю командную строку вместе с паролями, поэтому `/LOG` не используют. Переменная окружения
в командную строку не попадает. При новой установке PostgreSQL пароль суперпользователя на время
создания кластера появляется в командной строке процесса установщика EDB: так устроен этот
установщик.

### Код возврата и журналы

| Код    | Значение                                                                                                         |
| ------ | ---------------------------------------------------------------------------------------------------------------- |
| `0`    | Машина в рабочем состоянии, все проверки пройдены                                                                |
| `7`    | Установщик отказался работать. Причина записана последней строкой в самом новом журнале `setup-*.log`            |
| другой | Сбой самой программы установки. Машина в рабочее состояние не приведена                                          |

Журналы лежат в `C:\Program Files\SemiBase Setup\Logs`, паролей в них нет:

- `setup-<ггггммдд-ччммсс>.log` — причина отказа. Если отказала утилита, строка называет её журнал.
- `site-<ггггммдд-ччммсс>.log` — полный вывод утилиты за каждый запуск, успешный или нет.

Папка `C:\Program Files\SemiBase Setup` не зависит от выбранной папки установки. Создать или
изменить что-либо в `C:\Program Files` может только администратор, поэтому обычный пользователь
не подменит ни журналы, ни копию утилиты.

### Запуск с окнами

Без `/VERYSILENT` установщик показывает свои страницы. После выбора папки идёт страница паролей:
поля суперпользователя и `scada_writer` скрывают ввод и заполнены из параметров или переменных
окружения. Поле суперпользователя обязательно. Поле `scada_writer` обязательно, когда на машине не
зарегистрирован ни один PostgreSQL. Отказ установщик показывает в своём окне и пишет в тот же
журнал `setup-*.log`.

### Что делает установщик

Состояние PostgreSQL установщик определяет по реестру `HKLM\SOFTWARE\PostgreSQL`, который ведёт
установщик PostgreSQL от EDB, а не по списку служб. Строки проверяются сверху вниз, срабатывает
первая подходящая.

| На машине                                                                                                       | Установщик                                                                                                                                  |
| --------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| PostgreSQL 17 зарегистрирован (`Installations\postgresql-x64-17`), у него есть суперпользователь, каталог данных и служба | Работает с ним, даже если зарегистрированы и другие версии. Порт и суперпользователь берёт из реестра. Службу переводит в автоматический запуск и запускает |
| PostgreSQL 17 зарегистрирован, но установка неполная: версия не 17.x, нет суперпользователя или нет `PG_VERSION` в каталоге данных | Отказывает. Так выглядит неудачная установка PostgreSQL                                                                        |
| PostgreSQL 17 зарегистрирован, но его службы или порта нет                                                      | Отказывает: такую регистрацию установщик не чинит                                                                                           |
| Зарегистрирована другая версия, 17 нет                                                                          | Отказывает и называет версию, службу и порт                                                                                                 |
| Ничего не зарегистрировано, но порт 5432 занят                                                                  | Отказывает: незнакомый сервер установщик не трогает                                                                                         |
| Ничего не зарегистрировано, но `C:\Program Files\PostgreSQL\17\data` не пуст                                    | Отказывает: существующие данные установщик не перезаписывает                                                                                |
| Ничего не зарегистрировано, порт свободен, каталога данных нет                                                  | Требует пароль `scada_writer`, ставит PostgreSQL 17 и дальше работает с ним, как в первой строке                                            |

Новая установка PostgreSQL 17: порт 5432, служба `postgresql-x64-17`, суперпользователь `postgres`,
каталог данных `C:\Program Files\PostgreSQL\17\data`, локаль `C`, кодировка UTF8, без pgAdmin и
Stack Builder. Когда служба запущена, установщик до 60 с ждёт, пока порт на `localhost` начнёт
принимать подключения, и запускает утилиту:

```powershell
semibase.exe site --port <порт> --superuser <суперпользователь> --expected-major 17 --restart-service <служба>
```

С базой утилита поступает так:

| В базе                                       | Утилита                                                                                             |
| -------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| База `scada_archive` уже есть                | Использует её как есть                                                                              |
| Роль уже есть, пароль для неё не передан     | Оставляет прежний пароль                                                                            |
| Роли нет, пароль для неё не передан          | Отказывает. Пароль `scada_writer` нужен только при первой установке                                 |
| Таблица `public.trends` уже есть             | Не изменяет её. Если `semiplot` не может её читать, текст ошибки называет команду, которая это чинит |
| Кластер PostgreSQL 17 с локалью не `C`       | Использует как есть: новая база наследует локаль `template1` этого кластера                         |
| Сервер не версии 17                          | Отказывает                                                                                          |

Повторные запуски и сбои:

| Случай                                              | Результат                                                                                          |
| --------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| Повторный запуск установщика                        | Работает с установленным PostgreSQL 17 и перезапускает службу, только если настройки ждут перезапуска |
| Установщик PostgreSQL завершился с ошибкой          | Отказ с путём к журналу установщика PostgreSQL. Следующий запуск видит неполную установку и отказывает |
| Утилита отказала после установки PostgreSQL          | PostgreSQL остаётся. Повторный запуск с тем же паролем суперпользователя работает с ним              |
| Удаление SemiBase                                   | Удаляется только `semibase.exe` из папки установки                                                 |

Перезапуск службы разрывает подключения SCADA. Список настроек, которые ждут перезапуска, выводит
запрос `SELECT name FROM pg_settings WHERE pending_restart`. Если он не пуст, перед запуском
установщика на работающей установке остановите SCADA.

### Удаление

`unins000.exe` в папке установки, по умолчанию `C:\Program Files\SemiBase` (или «Установка и
удаление программ»), удаляет только `semibase.exe` из этой папки. PostgreSQL, его данные, роли,
журналы и копия утилиты в `C:\Program Files\SemiBase Setup` остаются.

## Порядок ввода в эксплуатацию

Порядок важен: утилита выставляет права на чтение до того, как создаёт `public.trends`, поэтому
установщик отрабатывает до первого запуска SCADA.

1. Запустить установщик, как в разделе [запуск без окон](#запуск-без-окон), и убедиться, что код
   возврата `0`. При другом коде перейти к
   [восстановлению](#восстановление-после-отказа-установщика).

   Код `0` гарантирует: PostgreSQL 17 работает как служба с автоматическим запуском, настройки
   сервера применены, служба перезапущена, если они этого ждали. Архивная база, три роли, права и
   права по умолчанию созданы, пять таблиц SemiPlot, функция `semiplot_register_new_pens()` и
   `public.trends` (с партицией `tpdefault`) на месте. `semiplot` читает `public.trends`, вызывает
   функцию регистрации перьев, пишет свои таблицы, не может добавить, удалить или перенумеровать
   перо и не может писать в архив. Отдельной проверки после этого не требуется.

2. Запустить проект Simple-Scada против базы. Проект подключают к `localhost` или `127.0.0.1`:
   сервер принимает подключения только с этой машины. Мы рассчитываем, что таблицу `trends` он
   застанет готовой, оставит её как есть и дальше создаст дневные партиции и `messages` сам.
   **Это предположение не проверено на реальном проекте.** На первом запуске включите
   `log_statement = 'all'` и прочитайте в журнале PostgreSQL, какие DDL-команды SCADA выдала:
   если она создаёт или изменяет `trends`, порядок ввода в эксплуатацию нужно пересмотреть.

3. Запустить SemiPlot и в редакторе перьев нажать «Обновить список перьев». Кнопка добавляет в
   `semiplot_tags` по перу на каждую переменную, которую SCADA уже записала в `trends`, с
   настройками по умолчанию. При запуске SemiPlot перья не добавляет: переменные, появившиеся
   позже, добавляет следующее нажатие кнопки. Дальше перья меняют в том же редакторе. Вручную их
   не добавляют, а удалить перо может только суперпользователь.

4. Записать файл подключения SemiPlot `connection.yaml`: хост `127.0.0.1`, порт PostgreSQL 17,
   роль `semiplot`, пароль `semiplot`. Порт при новой установке `5432`; у уже стоявшего
   PostgreSQL 17 он записан в значении `Port` ключа
   `HKLM\SOFTWARE\PostgreSQL\Services\postgresql-x64-17`, и журнал `site` называет его в последней
   строке, `Done: site completed against localhost:<порт>/scada_archive`. Часовой пояс в файле
   не указывают: SemiPlot работает на машине SCADA и читает архив в её часовом поясе.

Если проверка в конце работы утилиты не прошла, установщик возвращает `7`, а журнал `site`
называет причину. Если `semiplot` не имеет доступа к `trends`, значит таблица была создана раньше,
чем выставлены права по умолчанию; способ починки назван в тексте ошибки. Если роль не может писать
свою таблицу или, наоборот, держит лишнее право на архив, в тексте ошибки названы таблица, операция
и команда `GRANT` или `REVOKE`, которая это чинит. Если роль может добавить, удалить или
перенумеровать перо, в тексте ошибки названа команда `REVOKE`, которая забирает лишнее право у
`semiplot`, у `PUBLIC` или у роли, в которую входит `semiplot`.

## Восстановление после отказа установщика

Отказ установщика — это код возврата `7`. Восстановление идёт так:

1. Прочитать последнюю строку самого нового журнала
   `C:\Program Files\SemiBase Setup\Logs\setup-*.log`.
2. Найти её начало в таблице ниже и сделать то, что там сказано.
3. Запустить установщик снова.

Отказы из-за паролей и из-за состояния PostgreSQL установщик выдаёт до любых изменений в
PostgreSQL; до них он только кладёт копию утилиты в `C:\Program Files\SemiBase Setup`. Отказ
установщика PostgreSQL или утилиты может прийти, когда PostgreSQL уже установлен или служба уже
запущена.
Неверный пароль суперпользователя уже стоящего PostgreSQL 17 обнаруживает только утилита, то есть
после того, как служба переведена в автоматический запуск и запущена.

| Строка в журнале                                                                                     | Что делать                                                                                     |
| ---------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `No superuser password`                                                                              | Передать пароль суперпользователя параметром или переменной                                    |
| `No scada_writer password`                                                                           | Установщик ставит PostgreSQL и создаёт `scada_writer`: передать пароль этой роли               |
| `The superuser password must ...`, `The scada_writer password ... must be printable ASCII`             | Выбрать пароль по [правилам](#параметры-и-пароли). Правила для пароля суперпользователя действуют только при новой установке PostgreSQL |
| `The /SUPERPASSWORD value does not reach Setup as typed`, то же для `/WRITERPASSWORD`                 | Передать пароль переменной окружения; пароль с `"` доходит только так                          |
| `Setup argument ... is not a switch Setup reads`                                                     | Пароль с пробелом разделился на два слова, или в командной строке есть ключ, которого установщик не знает. Пароль передать переменной окружения или взять параметр в кавычки, как в разделе [параметры и пароли](#параметры-и-пароли) |
| `... is not a complete PostgreSQL 17 installation`                                                   | Так выглядит неудачная установка PostgreSQL. Удалить её программой `uninstall-postgresql.exe`, путь к которой назван в строке, и [дождаться конца удаления](#удаление-postgresql) |
| `... names no service`, `... names service ..., which does not exist`, `... has no Port value`, `... has a Super User or Service ID that contains " or %` | Регистрация PostgreSQL 17 в реестре не совпадает со службами или её значения нельзя передать утилите. Если сервер работает, подготовить его [утилитой вручную](#ручной-запуск-утилиты). Иначе удалить остатки программой `uninstall-postgresql.exe` из папки установки PostgreSQL и [дождаться конца удаления](#удаление-postgresql) |
| `PostgreSQL 17 is not registered, and another major is`                                              | Установщик работает только с PostgreSQL 17 и не ставит его рядом с другой версией. Либо перенести данные старой версии на 17 через `pg_upgrade` в плановый простой, либо удалить старую версию, если её данные не нужны. Готовить старую версию утилитой вручную бесполезно: каждый следующий запуск установщика всё равно откажет |
| `No PostgreSQL is registered, but localhost:5432 accepts TCP`                                        | На порту работает сервер, которого нет в реестре: служба, поставленная не установщиком EDB, сервер, запущенный вручную, или контейнер. Найти процесс: `Get-Process -Id (Get-NetTCPConnection -LocalPort 5432 -State Listen).OwningProcess`. Контейнер остановить: утилита закрыла бы его для подключений извне. Сервер PostgreSQL 17 на этой машине можно подготовить [утилитой вручную](#ручной-запуск-утилиты), иначе остановить его |
| `No PostgreSQL is registered, but C:\Program Files\PostgreSQL\17\data exists and is not empty`       | Данные остались после прерванной установки или после удаления PostgreSQL: удаление каталог данных не трогает. Если данные не нужны, удалить каталог. Установщик их никогда не перезаписывает |
| `The PostgreSQL installer exited with code`                                                          | Причина записана в журнале установщика PostgreSQL, путь к нему назван в строке. Следующий запуск увидит неполную установку: удалить её, как в строке про неполную установку |
| `sc.exe config ...`, `sc.exe start ...`, `... accepted no TCP connection within 60 s`                 | Служба не запустилась или сервер не принял подключение. Причина записана в журнале сервера, в папке `log` каталога данных, и в журнале событий Windows. Устранить её |
| `semibase site exited with code`                                                                     | Причина записана в журнале `site`, путь к нему назван в строке. `password authentication failed` значит неверный пароль суперпользователя. `role scada_writer does not exist and no password was given to create it` значит, что на уже стоящем PostgreSQL 17 роли ещё нет: передать пароль `scada_writer`. Если служба осталась остановленной, см. [ошибки перезапуска службы](#ошибки-перезапуска-службы) |
| `Setup could not ...`, `Setup stopped on an error`                                                   | Не скопировалась утилита в `C:\Program Files\SemiBase Setup`, не запустился `powershell.exe`, `cmd.exe` или установщик PostgreSQL (его может заблокировать антивирус), не задались переменные с паролями или не записался временный файл. Запустить установщик снова; если отказ повторяется, приложить журнал к обращению в поддержку |

### Удаление PostgreSQL

`uninstall-postgresql.exe` завершается раньше, чем удаляет что-либо: работу делает его копия
`_uninstall*.000` в папке `%TEMP%`. Перед следующим запуском установщика дождитесь её завершения:

```powershell
while (Get-CimInstance Win32_Process | Where-Object { $_.Name -like '_uninstall*.000' }) { Start-Sleep -Seconds 1 }
```

Каталог данных удаление не трогает. Если он остался и не пуст, следующий запуск откажет из-за него.

### Ошибки перезапуска службы

Утилита запускает службу, только когда старый сервер завершил работу и порт перестал отвечать.
Если журнал `site` сообщает, что служба остановлена и такой останется, дождитесь, пока
`Test-NetConnection localhost -Port 5432` покажет `TcpTestSucceeded : False` и
`Get-Service postgresql-x64-17` покажет `Stopped`, и запустите службу командой
`Start-Service postgresql-x64-17`.

Если служба остановилась сразу после запуска, журнал `site` сообщает, отвечает ли сервер на порту.
Если ничего не отвечает, сервер завершился при старте. Причина записана в журнале сервера, в папке
`log` каталога данных. Если журнал называет настройку, которую записала утилита (например, серверу
не хватило памяти на `shared_buffers = 2GB`), удалите эту строку из `postgresql.auto.conf` в
каталоге данных и запустите службу командой `Start-Service postgresql-x64-17`. Повторный запуск
установщика запишет строку снова и так же остановит службу, поэтому сначала устраните причину.
Если сервер отвечает, служба не дождалась конца его старта, и сервер работает вне службы. Когда он
начнёт принимать подключения, остановите его командой `pg_ctl stop -D <каталог данных>`
(`pg_ctl.exe` лежит в папке `bin` установки PostgreSQL, каталог данных указан после `-D` в пути к
исполняемому файлу службы) и запустите службу командой `Start-Service postgresql-x64-17`.

Если установщик или утилиту прервали во время перезапуска (завершили процесс, вышли из системы),
служба может остаться остановленной. Проверьте её командой `Get-Service postgresql-x64-17` и, если
она остановлена, запустите командой `Start-Service postgresql-x64-17`.

### Ручной запуск утилиты

Для состояний, с которыми установщик не работает, утилиту запускают сами. Каждый запуск
установщика первым делом, ещё до проверки паролей, кладёт свою утилиту в
`C:\Program Files\SemiBase Setup\semibase.exe`. Поэтому она есть и на машине, где установщик ни
разу не завершился успешно, и не нужно ни скачивать её, ни собирать. Удаление SemiBase эту копию
не трогает. Заменить её может только администратор, поэтому запускать её от имени администратора
с паролями в окружении безопасно.

Утилита готовит только PostgreSQL 17 и откажет серверу другой версии. Ей нужны порт сервера,
суперпользователь и, если сервер работает как служба Windows, имя службы:

| Значение          | PostgreSQL 17 в реестре EDB                                                                                              | Сервер, которого нет в реестре                 |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------- |
| Порт              | Значение `Port` ключа `HKLM\SOFTWARE\PostgreSQL\Services\<служба>`; если его нет, `port` в `postgresql.conf` каталога данных | `5432`: на нём установщик и нашёл сервер       |
| Суперпользователь | Значение `Super User` ключа `HKLM\SOFTWARE\PostgreSQL\Installations\postgresql-x64-17`                                   | Тот, кто ставил сервер, обычно `postgres`      |
| Служба            | Значение `Service ID` того же ключа; если его нет или такой службы нет, поиск ниже                                        | Поиск ниже                                     |

Службу PostgreSQL находят по `pg_ctl` в пути к её исполняемому файлу. Каталог данных службы
указан там после `-D`:

```powershell
Get-CimInstance Win32_Service | Where-Object PathName -like '*pg_ctl*' | Format-List Name, State, StartMode, PathName
```

Утилита не работает с отключённой или остановленной службой, поэтому службу переводят в
автоматический запуск и запускают. Дальше в окне PowerShell от имени администратора, подставив
значения из таблицы:

```powershell
$port = 5432
$superuser = 'postgres'
$service = 'postgresql-x64-17'
Set-Service $service -StartupType Automatic; Start-Service $service
$env:SEMIBASE_SUPER_PASSWORD = [Net.NetworkCredential]::new('', (Read-Host 'Пароль postgres' -AsSecureString)).Password
$env:SEMIBASE_WRITER_PASSWORD = [Net.NetworkCredential]::new('', (Read-Host 'Пароль scada_writer' -AsSecureString)).Password
$env:SEMIBASE_PLOT_PASSWORD = 'semiplot'
& 'C:\Program Files\SemiBase Setup\semibase.exe' site --port $port --superuser $superuser --expected-major 17 --restart-service $service
$LASTEXITCODE
```

Пароль `scada_writer` нужен, только если роли ещё нет; иначе строку пропускают. Пароль `semiplot`
задан тем же, что задаёт установщик. Перед любыми изменениями утилита сверяет каталог после `-D` в
пути к исполняемому файлу службы с каталогом данных сервера на порту. Если они не совпадают,
`--restart-service` называет не ту службу, и утилита завершается с ошибкой, ничего не изменив.

Если сервер работает не как служба Windows, например запущен вручную через `pg_ctl start`, строку
`Set-Service` и флаг `--restart-service $service` убирают. Тогда утилита сообщает, какие настройки
ждут перезапуска, и сервер перезапускают вручную. Контейнер так не готовят: после перезапуска
сервер слушает только локальный интерфейс, и контейнер закрывается для подключений извне.

Код `0` значит то же, что код `0` установщика.

## Утилита semibase.exe

Утилита — скрипт установки: одна команда приводит экземпляр в заданное состояние и завершается.
Пароли существующих ролей она меняет только при явной передаче флага или переменной окружения.

```powershell
.\semibase.exe --help              # список команд
.\semibase.exe site --help         # флаги конкретной команды
```

| Команда   | Действие                                                                                                                                                                 |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `site`    | Машина установки: настройки сервера через `ALTER SYSTEM`, затем архивная база, роли, права доступа, пять таблиц SemiPlot и `public.trends`                               |
| `bench`   | Временный контейнер (тестовый стенд, база для разработки): то же самое без настроек сервера: память в них рассчитана на машину установки, а прослушивание только локального интерфейса закрыло бы контейнер от клиентов |
| `version` | Печать ревизии сборки                                                                                                                                                     |

Обе команды заканчиваются проверкой: `semiplot` читает `public.trends` и версию схемы, вызывает
функцию регистрации новых перьев, пишет свои собственные таблицы и не может ни писать в архив, ни
менять версию схемы, ни создавать объекты в схеме `public`. Ненулевой код возврата означает, что
заявленное состояние не достигнуто.

При обращении за поддержкой приложите вывод `semibase version`: он однозначно называет сборку
утилиты на машине.

### Пароли

Пароли утилита берёт из флагов или переменных окружения, флаг важнее переменной. Файлов с
паролями утилита не читает и сама их не записывает. Флаг с паролем, набранный в командной
строке, PowerShell сохраняет в истории команд на диске. Поэтому пароли задают переменными
окружения, а значение вводят по запросу `Read-Host`, как в
[ручном запуске утилиты](#ручной-запуск-утилиты).

Команды, которые задают пароль роли, в журнал PostgreSQL не попадают: ни при
`log_statement = 'all'`, ни при журналировании медленных или ошибочных запросов. На соединениях
суперпользователя утилита отключает журналирование своих команд, поэтому роль, под которой она
подключается, должна быть суперпользователем.

| Роль           | Флаг                | Переменная окружения       |
| -------------- | ------------------- | -------------------------- |
| `postgres`     | `--super-password`  | `SEMIBASE_SUPER_PASSWORD`  |
| `scada_writer` | `--writer-password` | `SEMIBASE_WRITER_PASSWORD` |
| `semiplot`     | `--plot-password`   | `SEMIBASE_PLOT_PASSWORD`   |

Пароли ролей нужны только на первом запуске, который эти роли создаёт. Когда роли уже есть,
достаточно пароля суперпользователя; пароль `semiplot` тогда лишь включает дополнительную проверку
входа под этой ролью (только по TCP).

### Основные флаги

| Флаг                | По умолчанию    | Назначение                                                    |
| ------------------- | --------------- | ------------------------------------------------------------- |
| `--host`            | `localhost`     | Адрес сервера или каталог unix-сокета (`/var/run/postgresql`) |
| `--port`            | `5432`          | Порт сервера                                                  |
| `--database`        | `scada_archive` | Имя архивной базы                                             |
| `--superuser`       | `postgres`      | Суперпользователь, под которым подключается утилита           |
| `--expected-major`  | не проверяется  | Требуемая мажорная версия сервера                             |
| `--restart-service` | не задан        | Только `site` в Windows: служба PostgreSQL, которую утилита перезапускает, если настройки ждут перезапуска. Требует `--host` `localhost`, `127.0.0.1` или `::1` и запуска от имени администратора. Отключённую, остановленную или обслуживающую другой каталог данных службу утилита не трогает и завершается с ошибкой; только что запущенную службу ждёт до двух минут |

Полный перечень — `semibase <команда> --help`.

## Роли

Ролей четыре. Суперпользователя создаёт установщик СУБД, три остальные — утилита.

| Роль           | Кто использует             | Доступ                                              |
| -------------- | -------------------------- | --------------------------------------------------- |
| `postgres`     | Утилита развёртывания      | Суперпользователь: подключается сама утилита, ей же принадлежат таблицы `semiplot_*` |
| `scada_writer` | Simple-Scada 2             | Владеет архивными таблицами и пишет в них, создаёт дневные партиции, выполняет ретеншн |
| `semiplot`     | SemiPlot и другие клиенты  | Чтение `trends` и `messages`; чтение `semiplot_tags` и изменение настроек пера в ней, но не его `id`; чтение и запись `semiplot_groups`, `semiplot_pen_groups` и `semiplot_markers`; чтение `semiplot_meta`; вызов функции `semiplot_register_new_pens()` |
| `semiplot_registrar` | Никто не входит под ней | Владеет функцией `semiplot_register_new_pens()`: чтение `trends`, добавление строк в `semiplot_tags` |

Роль `semiplot` ведёт собственный каталог перьев и метки времени: редактор SemiPlot сохраняет перо по тому же
соединению, по которому читает историю. Права выданы по таблицам, поэтому писать в архив она
не может — эту проверку утилита выполняет на каждом запуске.

Строка `semiplot_tags` привязана к номеру переменной SCADA. SemiPlot меняет в ней только
настройки пера: имя, единицы, формат, цвет, стиль линии, показ при старте, границы шкалы при старте
и логарифмическая шкала при старте. Добавить перо напрямую, удалить его или сменить ему `id` роль
не может, и утилита на каждом запуске проверяет, что эти три команды ей запрещены. Новые перья
добавляет только функция `semiplot_register_new_pens()`, и только для переменных, которые SCADA уже
записала в `trends`.

Таблицы `semiplot_*` принадлежат суперпользователю: их создаёт то соединение, которое выполняет
DDL. Права `CREATE` в схеме `public` у роли `semiplot` нет — утилита забирает его у `PUBLIC`
на каждом запуске, потому что PostgreSQL 14 всё ещё выдаёт его всем по умолчанию, — поэтому
ничего сверх этих таблиц роль не добавит.

Таблицу `public.trends` утилита создаёт от имени `scada_writer`: владельцем должна быть та же
роль, от которой пишет SCADA, иначе `semiplot` получит доступ не тем путём, каким он работает
в эксплуатации. Утилита берёт роль командой `SET ROLE` на соединении суперпользователя и не
входит отдельно под `scada_writer`: владелец и права на таблицу выходят те же, а `pg_hba.conf`
править не придётся.

## Таблицы SemiPlot

Утилита создаёт пять таблиц и задаёт их схему. SemiPlot меняет настройки перьев в
`semiplot_tags`, ведёт группы в `semiplot_groups` и `semiplot_pen_groups` и метки времени в
`semiplot_markers`, а `semiplot_meta` пишет только сама утилита.

| Таблица               | Что хранит                                                                                  |
| --------------------- | ------------------------------------------------------------------------------------------- |
| `semiplot_tags`       | Перо: `id` из `trends`, имя, единицы, формат числа, цвет `#RRGGBB`, стиль линии, показ при старте, границы шкалы при старте, логарифмическая шкала при старте |
| `semiplot_groups`     | Имена групп перьев                                                                            |
| `semiplot_pen_groups` | Принадлежность пера группам. Перо может входить в несколько групп и ни в одну                 |
| `semiplot_markers`    | Метки времени на графике: момент и необязательная подпись длиной до 80 символов. Метка не привязана к дневной партиции архива и переживает её удаление |
| `semiplot_meta`       | Одну строку: версию схемы                                                                     |

Перья появляются в `semiplot_tags` по кнопке «Обновить список перьев» в редакторе перьев SemiPlot,
при запуске SemiPlot их не добавляет. Кнопка вызывает функцию `semiplot_register_new_pens()`: она
добавляет по строке на каждый номер переменной из `trends`, у которого строки ещё нет, и возвращает
число добавленных. Новое перо называется своим номером, получает цвет из фиксированной палитры, по
умолчанию скрыто при старте, масштабируется автоматически и открывается на линейной шкале. Перо
переменной, которую SCADA перестала писать, остаётся: её история по-прежнему лежит в `trends`.
Номера переменных SCADA считаются неотрицательными: перо с отрицательным номером остаётся без
цвета, и цвет выбирает SemiPlot.

Функцией владеет отдельная роль `semiplot_registrar`, под которой нельзя войти. Функция
выполняется с её правами, а не с правами суперпользователя: чтение `trends` и добавление строк в
`semiplot_tags`, больше ничего. Вызвать функцию может только `semiplot`: право `EXECUTE`, которое
PostgreSQL выдаёт `PUBLIC` на любую новую функцию, утилита забирает. На архиве из 50 переменных за
один день первый вызов занимает около 13 мс, повторный — около 2 мс. Время растёт пропорционально
числу переменных, умноженному на число дневных партиций. Для 500 переменных за год это оценка, а
не замер: около 2,6 с на вызов, который ничего не добавляет, и около 4,8 с на вызов, который
добавляет все переменные.

Права ограничивают оператора SemiPlot, но не SCADA. Под ролью `scada_writer` работает сама
Simple-Scada 2 на той же машине, и ей доверяют: она владеет `trends` и и так может переписать или
удалить любую запись архива. Кто читает таблицу, тот выполняет код, который к ней добавил её
владелец: политика защиты строк на `trends` или представление на её месте вызывает свои функции с
правами читающей роли. Поэтому `scada_writer` может действовать от имени `semiplot`, когда та
читает `trends`, и от имени `semiplot_registrar`, когда выполняется функция. Права `semiplot`
держат другую границу: оператор SemiPlot меняет настройки перьев, группы и метки времени, но не может добавить,
удалить или перенумеровать строку `semiplot_tags`. Отдельная роль-владелец всё равно нужна: если бы
функцией владел суперпользователь, `scada_writer` через представление получила бы права
суперпользователя на весь кластер. Под `semiplot_registrar` ей доступны только чтение `id` и
добавление строк в `semiplot_tags` и сама функция.

Версия схемы — нижняя граница, а не точное совпадение: SemiPlot отказывается работать
с базой, версия которой ниже нужной ей, и принимает базу с версией выше. Этот выпуск пишет `1`.
